# Deploying FairShare (free demo)

FairShare is a demo, so it runs on free tiers: **$0**, no credit card.

```
Browser ──► Cloudflare Pages   fairshare-web (static build)       instant, global CDN
       └──► Render (free)      fairshare-api (this repo, Docker)  sleeps after 15 min idle
                 └──► Neon (free)  PostgreSQL                     sleeps after 5 min idle
```

| Part | Service | Why |
|---|---|---|
| Web app | Cloudflare Pages | Free static hosting, auto-builds from GitHub, single-page-app routing out of the box. The home page loads instantly even while the API sleeps. |
| API | Render free web service | Builds this repo's `Dockerfile` as is. Sleeps after 15 min without traffic; the next request waits up to about a minute while it wakes. 750 free hours/month covers one always-on service. |
| Database | Neon free Postgres | No expiry, wakes in under a second. (Render's free Postgres is deleted after 30 days; Supabase's free tier pauses after a week of inactivity.) |

Put the API and the database **in the same region** (Singapore is closest to Sri Lanka).

> Free-tier terms change. Check each provider's pricing page when you sign up.

---

## 1. Database — Neon

1. Sign up at neon.com and create a project in **AWS Asia Pacific (Singapore)**.
2. Copy the **direct** connection string (turn *off* "Connection pooling"; the host must **not**
   contain `-pooler`). It looks like
   `postgresql://user:password@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

No manual schema step: the API applies its EF Core migrations when it starts, and retries while
the database wakes up.

## 2. API — Render

1. Push this repo to GitHub.
2. Render → **New → Blueprint** → select the repo. `render.yaml` defines the service (Docker, free
   plan, Singapore, health check `/health`, auto-deploy on push to `master`).
3. Fill in the prompted values:

| Variable | Value |
|---|---|
| `ConnectionStrings__DefaultConnection` | Neon's direct connection string from step 1 (URL form is fine) |
| `AllowedOrigins` | The web app's URL from step 3, e.g. `https://fairshare.pages.dev` — set a placeholder now and update it after step 3 |

   `Jwt__Key` is generated by Render automatically; `ASPNETCORE_ENVIRONMENT` is `Production`.
4. Deploy, then open `https://<your-service>.onrender.com/health` → `{"status":"ok"}`.

**Without the Blueprint:** New → Web Service → Docker, plan Free, region Singapore, health check
path `/health`, and set the variables above plus `ASPNETCORE_ENVIRONMENT=Production` and a random
`Jwt__Key` of at least 32 characters (e.g. `openssl rand -base64 48`).

## 3. Web app — Cloudflare Pages

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** → `fairshare-web`.
2. Build settings: framework preset **None**, build command `npm run build`, output directory
   `dist`.
3. Environment variable (Production): `VITE_API_BASE` = `https://<your-service>.onrender.com/api`.
   The build fails on purpose if this is missing, so a deploy can never point at localhost.
4. Deploy. Every push to `master` redeploys; pull requests get preview URLs.
5. Back on Render, set `AllowedOrigins` to the Pages URL (e.g. `https://fairshare.pages.dev`).
   Preview URLs aren't allowed by CORS unless you add them too.

## 4. Check it

- Create a group, add members and expenses, check balances and "Who pays whom".
- Open a shared `/group/<id>` link directly in a new tab.
- Leave it idle 20 minutes, then reload: the page shows "Waking up the server…" for up to about
  a minute, then works normally.

## Configuration reference

| Setting (env var) | Required | Notes |
|---|---|---|
| `ConnectionStrings__DefaultConnection` | Yes | Npgsql key/value form or a `postgres://` / `postgresql://` URL. |
| `Jwt__Key` | Yes | ≥ 32 random characters. The API refuses to start with a missing, short or placeholder key. |
| `AllowedOrigins` | Yes | Comma-separated browser origins allowed by CORS. A warning is logged at startup if empty. |
| `ASPNETCORE_ENVIRONMENT` | Yes | `Production` (Development enables the Scalar docs and log files). |
| `PORT` | No | Set by most platforms; the API listens on it (default 8080). |
| `RateLimit__ReadsPerMinute` | No | Per client IP; default 300. `/health` is never limited. |
| `RateLimit__WritesPerMinute` | No | Per client IP; default 60. Over any limit → `429` with `Retry-After`. |
| `RateLimit__WritesPerDay` | No | Per client IP; default 1,000. The guard on database growth. |
| `RateLimit__GroupsPerHour` | No | New groups per client IP; default 10. |
| `Limits__MembersPerGroup` | No | Default 30 (1 to 100). Over the limit → `409`. |
| `Limits__ExpensesPerGroup` | No | Default 1,000. Over the limit → `409`. |

The defaults are sized for about a dozen friends who may all share one IP address (one Wi-Fi
network or hotspot). The README's Security section explains each one.

## Operating notes

- **Cold starts.** To avoid the wake-up wait during a demo, open the app a minute before, or point
  a free uptime pinger (e.g. cron-job.org) at `/health` every 10 minutes. `/health` never touches
  the database, so Neon still sleeps and saves its free compute hours.
- **Logs.** Render → service → Logs (console output; no log files are written in Production).
- **Data.** Anyone with a group's link can edit it. This is a demo: don't put real financial data
  in it, and reset the database if it gets spammed (Neon → Branches → reset).
- **Upgrading later.** Render Starter ($7/month) removes the sleep; Google Cloud Run's free tier
  wakes faster but needs a billing account.
